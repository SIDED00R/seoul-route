# 안내 유지와 홈 탭 (이슈 #83)

작성일 2026-09-19. 안내를 시작하면 앱이 그 화면에 묶여 다른 경로를 볼 수 없었고, 뒤로가기를 누르면 안내가 끝났다.
안내를 화면에서 떼어 내고 홈을 세 탭으로 나눴다.

## 안내는 화면이 아니라 세션이 들고 있다

`app/lib/guide/guide_session.dart` 의 `GuideSession` 이 위치 스트림·구간 추적(`LegTracker`·`StepTracker`·`StopTracker`)·
음성(`VoiceGuide`)·알림창(`GuideStatusNotification`)·궤적 업로드(`TraceUploader`)를 들고 있다. 화면(`GuideScreen`)은
`ChangeNotifier` 로 이 객체를 듣기만 하고 지도·카드·버튼만 그린다.

- 안내 화면을 닫아도(뒤로가기·탭 이동) 세션은 살아 있다. 위치 기록·음성·알림창이 그대로 이어지고 서버 trip 도 열려 있다.
- 끝내는 것은 `end()` 뿐이다 — "안내 종료" 버튼. 남은 샘플을 보내고 trip 을 닫아 서버가 이번 안내의 속도를 프로파일에
  반영한다.
- 진행 중인 안내는 `app/lib/guide/active_guide.dart` 의 `ActiveGuide.instance` 에 하나만 둔다. 위치 스트림과 알림창이
  하나뿐이라 동시에 둘은 할 수 없다.
- 다른 여정으로 안내를 시작하려 하면 상세 화면이 물어보고(`replace_guide_confirm.dart`), 승낙하면 하던 안내를 `end()` 로
  끝낸 뒤 새로 시작한다. 같은 여정이면 묻지 않고 하던 안내를 이어서 보여 준다.

## 홈 탭 세 개

| 탭 | 내용 |
|---|---|
| 최근 경로 | 계정에 쌓인 지난 검색. 고르면 길찾기 탭에 출발·도착·경유지·구간 수단이 채워진다. 화면 `docs/app/30-recent-routes-tab.png` |
| 현재 경로 | 진행 중인 안내 요약과 "안내 화면으로". 안내 중이 아니면 비어 있다. 안내 중이면 탭에 점이 찍힌다. 화면 `docs/app/29-current-guide-tab.png` |
| 길찾기 | 지금까지의 검색 화면 |

탭은 `IndexedStack` 이라 오가도 길찾기 탭에 고른 출발·도착이 남는다.

## 최근 경로는 계정에 저장한다

사용자 결정(2026-09-19). 기기를 바꿔도 남는 대신 출발·도착 좌표가 서버 DB 에 쌓인다.

- 테이블 `recent_routes`(마이그레이션 `0005`): `user_id` · `dedup_key` · `request`(JSONB) · `searched_at`.
- `/routes/plan` 이 성공하면 서버가 그 요청을 그대로 기록한다(앱이 따로 부르지 않는다). 같은 검색은 한 줄로 묶고 시각만
  갱신한다 — 열쇠는 좌표를 소수 5자리(약 1m)로 줄인 출발·경유·도착과 구간 수단이다. 장소 이름은 넣지 않아 같은 자리를
  "현재 위치 · ○○빌딩" 과 검색 결과로 각각 고른 것이 따로 쌓이지 않는다.
- `GET /routes/recent` 는 새 것부터 20줄, `DELETE /routes/recent` 는 전부 지운다(앱의 "최근 경로 모두 지우기").
- 탈퇴(`DELETE /users/me`)하면 같이 지운다.
- 저장한 요청을 그대로 다시 보내면 같은 검색이 된다 — 경유지·구간 수단까지 재현된다.

  뒤로가기로 홈까지 나와도 알림창이 "남은 36분 · 7정거장 뒤 사당(4호선)에서 내리기" 로 계속 갱신됐다. "현재 경로" 탭에서
  안내 화면으로 돌아가 종료하니 탭이 비고 알림이 사라졌다. 오류 로그 0건.

## 알려진 한계

- 안내는 한 번에 하나다. 두 경로를 동시에 안내할 수 없다.
- 앱을 완전히 종료하면 안내도 끝난다(세션은 프로세스 안에 있다). 서버 trip 은 열린 채로 남는다.
- 최근 경로는 검색 시점만 남기고 어떤 후보를 골랐는지는 남기지 않는다 — 다시 고르면 그때의 후보를 새로 탐색한다.
