# 장소 검색 순서

`GET /places/search?q=&lat=&lon=` 은 카카오 로컬 키워드 검색을 서울 bbox 로 한정해 부르고 길찾기 용도 순서로 다시 세운다.
코드: `backend/internal/httpapi/places_handler.go`(호출), `places_rank.go`(순서).

## 지도 서비스들의 순위 기준 (공개 문서, 2026-09-29 조사)

| 서비스 | 공개된 기준 |
|---|---|
| Google 지도 | 지역 결과는 연관도(relevance, 검색어와 얼마나 맞는지)·거리(distance, 검색하는 사람과의 거리)·인지도(prominence, 얼마나 잘 알려졌는지)를 조합한다. 돈으로 순위를 살 수 없다. — [Google Business Profile 도움말](https://support.google.com/business/answer/7091?hl=en). 자동완성 API 는 `locationBias` 로 위치 쪽에 기울이되 범위 밖도 돌려주고, 예측은 "인지된 연관도" 순이다 — [Places Autocomplete](https://developers.google.com/maps/documentation/places/web-service/place-autocomplete) |
| 카카오맵 | 검색어와의 유사성·위치·인기도를 종합하고, 검색어마다 요소별 가중치를 달리해 자동으로 정한다(임의 조정 없음). 검색 중심점(내 위치/지도 중심)과 정렬(정확도/거리)을 고를 수 있다 — [카카오 고객센터](https://cs.kakao.com/helps_html/1073192984?locale=ko) |
| 네이버 지도(플레이스) | 공식 수식은 공개하지 않는다. 업계 분석에서 공통으로 드는 요소는 적합도(연관성)·인기도(검색·클릭·저장·리뷰)·거리, 그리고 최신성·신뢰도 |

세 곳 모두 **연관도 × 거리 × 인지도**의 조합이다. 인지도(클릭·리뷰 등 이용 기록)는 우리에게 없으므로 카카오 정확도순을 그 대용으로 두고, 우리는 연관도(이름이 검색어인 역)와 거리(사용자 위치)만 보탠다.

## 카카오 키워드 검색 실측 (2026-09-29)

- 검색어 전체가 지역 이름이면 `meta.same_name` 이 `keyword ""`·`selected_region "서울 강남구"` 이고, 결과는 그 지역의 명소다. "강남" → 서울선릉과정릉·압구정로데오거리 …(15위 안에 강남역 없음). 잠실·목동·여의도·신촌·성수·을지로·종로도 같다.
- 정확도순에 x·y 를 주면 체인·업종 검색(스타벅스·이마트·약국·편의점·카페)은 가까운 곳부터 세운다. 지역·명소 검색(강남·홍대)은 순서가 그대로이고 `distance` 만 붙는다.
- 지하철역 카테고리(`category_group_code=SW8`)로 "<검색어>역" 을 찾으면 같은 이름 역이 앞에, 그 이름으로 시작하는 역이 뒤에 온다("잠실역" → 잠실역 2·8호선, 잠실나루역, 잠실새내역).
- 앞부분만 친 단어는 찾지 않는다(자동완성 아님). "무교동북" → 무교동의 "동북보험대리점" 1건, "무교동북어" 부터 무교동북어국집. "스타벅"·"을지면"·"교동북어국집"(가운데 부분) → 0건. 공개 API 에 부분 일치 옵션이 없다 → 아래 상가 부분 일치로 메운다.

## 순서 규칙

1. 본 검색: `query=q`, 서울 bbox, 15건, 앱이 위치를 보냈으면 x·y(체인·업종은 카카오가 가까운 순으로 세우고 모든 결과에 거리가 붙는다).
2. 검색어가 지역 이름이거나 1위 이름이 검색어로 시작하지 않으면(`needsStationBoost`, 검색어가 "역"으로 끝나면 제외) 지하철역 검색 `"<q>역"` 을 한 번 더 불러, 이름이 정확히 "<q>역" 인 역을 맨 위에 둔다. 지역 이름이면 이어서 "<q>" 로 시작하는 역.
3. 카카오 결과 중 이름이나 업종 경로가 검색어를 그대로 품은 곳이 하나도 없으면(`kakaoUnderstood` 거짓 — 카카오가 입력 중인 단어를 다른 단어로 쪼개 읽은 것) 서울 상가 목록에서 이름(상호명+지점명, 공백·대소문자 무시)이 검색어를 품은 곳 5곳을 둔다. 앞부분 일치가 먼저, 그 안에서 위치가 있으면 가까운 순. 두 글자 미만은 찾지 않는다. 상가 목록은 공공데이터포털 「소상공인시장진흥공단_상가(상권)정보」(영업 중 상가, 분기 갱신, 로그인 없이 내려받기) 중 서울 554,092곳(2026-06-30 판)을 `python otp/fetch_shop_places.py` 로 `otp/data/shop-places-seoul.csv` 에 뽑아 API 가 기동 때 메모리에 올린다(적재 0.5초·힙 약 120MB, 검색 한 번 14~20ms, `SHOPS_CSV`, 없으면 이 단계 없음). 가게·음식점 위주라 아파트·공원·관공서는 카카오 결과로만 찾는다. 새 판(분기)이 나오면 스크립트를 다시 돌리고 API 를 재기동한다.
4. 그 뒤는 카카오 순서. 같은 장소는 한 번, 지하철역은 역 이름마다 하나(경로 탐색이 "…역" 이름을 같은 부모역으로 앵커링하므로 노선별 항목은 같은 출발·도착이다).
5. 역 검색이 실패하거나 3초(`stationTimeout`) 안에 답하지 않으면 본 검색 순서로 답한다.

앱은 검색 화면을 열 때 권한이 이미 있으면 마지막으로 알려진 위치(없으면 10초 안 새 위치)를 받아 두고, 받은 뒤의 검색부터 `lat`·`lon` 으로 보낸다. 결과 줄에 거리를 붙인다("1.2km · 카페 · 주소"). 에뮬레이터(위치 = 서울시청)에서 "starbucks" 검색 화면: `docs/app/39-place-search-distance.png`.

카카오 호출은 검색당 1회이고, 규칙 2의 조건(지역 이름이거나 1위 이름이 검색어로 시작하지 않음)이면 2회다(카페·약국처럼 같은 이름 역이 없어도 부른다).
