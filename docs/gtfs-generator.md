## 버스 변환 규칙

- `routes.txt`: `B_{busRouteId}`, route_type 3. 노선 유형(간선·지선·마을·광역·경기·인천) 모두 포함.
- `stops.txt`: `BS_{station}` (정류소 고유 ID), 좌표는 API 의 gpsX/gpsY.
- `trips.txt` + `frequencies.txt`: 노선을 회차 정류장(`transYn=Y`, 1,355노선 중 1,350개가 1개)에서 상행 `B_{id}_T0`(기점→회차, headsign=회차지, direction_id 0)·하행 `B_{id}_T1`(회차→종점, direction_id 1)으로 나눈다(회차가 없거나 양 끝이면 접미사 없는 한 방향). 한 trip 으로 두면 회차지를 지나 반대 방향까지 하차 없이 타는 경로가 생긴다. 각 방향의 frequencies 는 첫차+그 방향의 첫 기록 정류장까지 누적 소요부터 시작한다(하행이면 회차지 도착시각, bbox 클리핑으로 앞이 잘렸으면 첫 안쪽 정류장 — OTP 가 배차 trip 의 첫 stop_time 을 0 으로 정규화하므로 이렇게 맞춰야 절대시각 `_LAST` 와 일치한다). 배차는 첫차~막차 사이 `term`분, `exact_times=1`(첫차부터 배차간격 격자로 출발하는 고정 시간표).
- 서울 OSM bbox(126.70–127.25, 37.38–37.75) 밖 정류장(전체 18.8%, 504노선)은 `stop_times`·`stops` 에 넣지 않는다(도로망이 없어 OTP `IsolatedStop`). 누적 소요는 전 구간으로 계산해 안쪽 정류장의 시각은 그대로다. 안쪽 정류장이 2개 미만인 방향은 뺀다(`DroppedDirections`). `exact_times=0` 이면 OTP 2.10 이 승차마다 배차간격 전체를 대기로 더해 출발 위상과 무관하게 소요시간이 부풀었다(402번: 대기 9분 상수, 총 38.9분 → `1` 로 바꾸니 29.9분, 2026-09-12 실측). GTFS 의 `end_time` 은 배타적이고 OTP 2.10 도 `< end` 로 비교해(바이트코드 확인) 막차 시각 출발이 생성되지 않으므로, 막차 1회는 `B_{id}_LAST` 로 절대시각 stop_times 를 따로 둔다. 막차가 자정을 넘기면 24:xx 로 표기.
- `stop_times.txt`: `_T` 는 첫 정류장 00:00:00 기준 상대시각, `_LAST` 는 막차 시각 기준 절대시각. 정류장 간 소요 = `fullSectDist`(m) ÷ `sectSpd`(km/h) + 정차시간(노선유형별: 간선 38초, 지선·기타 30초, 마을·광역·공항 0). `sectSpd` 가 0 이면 18 km/h(placeholder).
- `calendar.txt`: 서비스 `ALL` 하나, 전 요일. **API 가 요일별 배차를 주지 않아 평일·주말이 같다** — 알려진 한계.
- 제외: 배차간격 없음 · 첫차·막차 파싱 실패 · 첫차==막차(API 가 시각을 모르면 둘 다 자정을 준다, 24시간 운행 아님) · 정류장 2개 미만 · 서울 bbox 안 정류장 2개 미만(2026-09-13 추가, 117인천 1개). 2026-09-12 실행에서 333개(bbox 제외 추가 후 334개). 그중 첫차==막차 82개에는 서울 노선 51개(지선 21·간선 18·광역 6·마을 3·순환 2·심야 1)가 포함되며, 이들만 지나던 서울 bbox 안 정류장 124곳이 그래프에서 빠진다. 유령 운행(새벽 3시 출근버스 안내)이 결측보다 해롭다고 보고 제외를 택했다. 나머지 251개는 대부분 경기·인천 진입 노선(245개)이고, 서울 노선 6개(자율주행 새벽A160·A504·A148·A741, 시티투어 TOUR04, 지선 8772)도 배차간격 결측으로 빠진다.

## 지하철 역 구내 통로 (이슈 #25, 2026-09-13)

- 부모역(`ST_<기준명>`, `stations.go`) 안 자식 stop(노선별 승강장)끼리 OTP 가 지상 도로망으로 환승 도보를 계산해 강남 2호선↔신분당선 182m 가 7.2분이었다(승강장 좌표가 도로에서 멀다). 파일럿 `transfers.txt` 의 `min_transfer_time`(178초)은 하한이라 도로 경로를 줄이지 못한다.
- `pathways.go`: 자식 stop 이 2개 이상인 역(229 승강장, 614 통로)에 (1) 승강장 쌍마다 양방향 walkway(통과시간 = transfers.txt 값, 없으면 직선거리÷1.0 m/s + 60초 — 단 500m 초과는 만들지 않는다: 기준명+800m 로 묶인 부모역이 실제 환승역이 아닐 수 있어서이고, 신촌 2호선↔경의중앙선 684m 가 그 경우. transfers 기반 151쌍 최대 390m·서울역 실재 폴백 5쌍 최대 434m) (2) 승강장마다 같은 좌표의 출입구(location_type 2, `EN_<stop_id>`)와 진입 120초·이탈 60초 단방향 통로. 출입구가 필요한 이유: OTP 는 통로가 있는 승강장을 도로에 직접 잇지 않는다(출입구 없이 넣자 `IsolatedStop` 273 → 480 실측) — 검증기도 같은 규칙(`pathway_unreachable_location` 229건 ERROR). 진입·이탈 초는 백엔드 `route/station_slack.go`(역 ID 앵커링 요청에 백엔드가 더하는 값)와 같아야 한다.
- 결과: 강남 환승 도보 7.2 → 3.0분, ODsay 대조 |Δ| 중앙값 3.3 → 1.0분(`docs/routing-accuracy.md`). `IsolatedStop` 273 → 292. 좌표 출발의 도로→출입구 접근은 출입구가 승강장 좌표에 있으면 도로 구간이 그대로이고 여기에 진입 2분이 더해진다(강남역 263m 옆 좌표 → 승강장 8.3분) → 아래 실제 출입구(이슈 #27). 알려진 한계: transfers.txt 쌍인데 부모역이 갈린 도봉산 1↔7호선 1쌍(파일럿 1호선 좌표가 1.1km 남쪽으로 보임)은 통로가 생기지 않아 지상 도보로 계산된다 — `gtfsgen build` 출력의 "부모역이 갈려 빠진 환승" 수로 확인.
- 실제 출입구(이슈 #27, 2026-09-13): `python otp/extract_entrances.py` 가 서울 OSM 의 `railway=subway_entrance` 2,457개(공사 중 3개 제외: `construction:railway` 태그·ref/description 의 "공사". 출구 번호 있음 2,434)를 `otp/data/subway-entrances.csv` 로 뽑고, `pathways.go` 가 가장 가까운 승강장이 350m 안인 역에 붙여 `EN_<부모>_<n>` 출입구를 만든다. 이름은 숫자형 ref 면 "강남 3번 출구", 그 밖의 ref("엘리베이터")는 OSM name, 없으면 "<역명> 출입구". 부모 평균 좌표 기준이면 승강장이 684m 떨어진 신촌은 출구 10개가 전부 탈락하고, 250m 면 청담 8개(KTDB 승강장에서 264~343m)가 탈락해 350m 로 정했다(오부착 1건: 상왕십리 4번 출구가 왕십리에 붙어 "왕십리 4번 출구" 2개 — 감수). 출입구↔승강장 통로는 500m 안 승강장에만, 진입 60초+거리÷1.0 m/s, 이탈 30초+거리(placeholder). 단일 승강장 역도 포함해 454역에 출입구 2,449개·통로 6,958개가 붙었고, OSM 출입구가 없는 다승강장 역 11곳(전부 bbox 밖)은 승강장 좌표 출입구로 폴백. 출입구 통로를 못 받는 승강장은 0(생성기 출력으로 확인). 결과: 강남역 263m 옆 좌표에서 강남(2호선) 승강장까지 도보 8.3 → 5.7분(308m 도로 + 진입), 역삼(단일 승강장) 150m 옆 좌표 → 4.8분. ODsay 대조(역 ID 요청)는 변화 없음. CSV 가 없으면 생성기가 경고하고 이전 방식으로 만든다.

## 소요시간 모델 정확도 (미보정, 알려진 한계)

- 정류장별 첫차 통과시각(`beginTm`)으로 교차검증하려 했으나 같은 차량 궤적이 아니라(마을버스 span 1,400분) 폐기.
- 파일럿 시간표와 노선명으로 604개 노선을 짝지어 비교한 결과 모델/시간표 비율 중앙값 1.21, 사분위 1.02~1.80. 매칭이 거칠고(정류장 수 불일치, 파일럿은 아침 1회차 기준) 방향이 일정하지 않아 보정 계수를 정할 근거가 못 된다.
- 2026-09-12 저녁 버스 실시간 위치(`getBusPosByRtid`)로 14개 노선 차량을 20초 간격 10분 추적(구간 1,135표본): 실측/모델(정차 0초) 전체 1.37, 간선 1.54·지선 1.49·마을 0.94·광역 0.86. 차이는 정차시간이라 노선유형별 상수를 더했다(`dwellSec`). `sectSpd` 자체는 준실시간으로 바뀌므로(70초 만에 110구간 중 10~29개 변경) 시간대별 프로파일은 `getStaionByRoute` 반복 수집으로 만들 수 있다. 상세 `docs/routing-accuracy.md`.
- 남은 한계: 저녁 한 시간대 표본이라 주간 첨두 미측정, 요일별 배차 없음(API 가 `term` 하나만 준다), shapes.txt 없음(버스 leg 거리 약 19% 과소), OSM bbox 밖 정류장 23%.

## 그 밖의 한계

- 도시철도는 국가교통DB 파일럿(2025-03 평일 1일)을 그대로 쓴다. 역 좌표·시간표 모두 파일럿 값. 갱신하려면 TAGO 역별 시간표 + 역 좌표(열린데이터광장 역사마스터 OA-21232) 결합 작업이 필요하다.
- `shapes.txt` 없음(getRoutePath 미사용). 지도 표시용이라 라우팅에는 영향 없다.
- OTP 는 같은 경로를 출발시각만 다르게 여러 개 반환한다(`exact_times=0` 에서는 1분 간격, `1` 에서는 배차 격자 간격). 백엔드가 leg 서명으로 중복 제거하고, 구간 분할 빔은 중복 제거 뒤에 자른다(빔 폭만큼만 받으면 복제로 채워져 실효 폭 1).
- 수집 클라이언트는 네트워크 오류(`*url.Error`)에서 키가 든 URL 을 벗겨 원인만 남긴다. 캐시·산출물·로그에 키 포함 0건 실측(2026-09-12).
