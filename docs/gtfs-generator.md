## 무엇을 만들었나

| 단계 | 명령 | 내용 |
|---|---|---|
| 수집 | `cd gtfs && go run ./cmd/gtfsgen fetch` | 서울시 버스 노선정보조회 API. 노선 목록은 노선명에 0~9 를 검색한 합집합(1,357개, 누락 0), 노선별 정류장 1,357회. 응답은 `gtfs/cache/*.json` 에 저장되고 있으면 건너뛴다 |
| 생성 | `cd gtfs && go run ./cmd/gtfsgen build` | 캐시 + 국가교통DB 파일럿 도시철도(`otp/data/202503_GTFS_DataSet`, route_type 1 만) → `gtfs/out/seoul-gtfs.zip` |
| 검증 | `java -jar gtfs-validator-8.0.1-cli.jar -i gtfs/out/seoul-gtfs.zip -o gtfs/out/validation -c kr` | MobilityData 검증기 |

## 버스 변환 규칙

- `routes.txt`: `B_{busRouteId}`, route_type 3. 노선 유형(간선·지선·마을·광역·경기·인천) 모두 포함.
  `route_color`·`route_text_color` 는 `internal/build/colors.go` 의 표에서 온다(이슈 #71): 지하철은 호선·노선 코드별
  고유색(1호선 0052A4 … 2호선 00A84D), 버스는 유형별(간선 0068B7·지선/마을 53B332·광역 E60012·순환 F2B70A·심야 3D5BAB).
  서울시 색 체계가 정하지 않은 유형(공항·인천·경기·관광·한강)은 비워 두고 앱이 기본 팔레트를 쓴다 — 2026-09-18 생성분에서
  버스 1,023개 중 400개가 그렇다. 서버는 이 컬럼을 `internal/routestyle` 로 읽어 leg 에 붙이므로 OTP 그래프를 다시 빌드할
  필요가 없다(zip 만 갈아 끼우고 api 를 재시작한다). 앱 화면은 `docs/app/23-route-colors.png`.
- `stops.txt`: `BS_{station}` (정류소 고유 ID), 좌표는 API 의 gpsX/gpsY.
- `trips.txt` + `frequencies.txt`: 노선을 회차 정류장(`transYn=Y`, 1,355노선 중 1,350개가 1개)에서 상행 `B_{id}_T0`(기점→회차, headsign=회차지, direction_id 0)·하행 `B_{id}_T1`(회차→종점, direction_id 1)으로 나눈다(회차가 없거나 양 끝이면 접미사 없는 한 방향). 한 trip 으로 두면 회차지를 지나 반대 방향까지 하차 없이 타는 경로가 생긴다. 각 방향의 frequencies 는 첫차+그 방향의 첫 기록 정류장까지 누적 소요부터 시작한다(하행이면 회차지 도착시각, bbox 클리핑으로 앞이 잘렸으면 첫 안쪽 정류장 — OTP 가 배차 trip 의 첫 stop_time 을 0 으로 정규화하므로 이렇게 맞춰야 절대시각 `_LAST` 와 일치한다). 배차는 첫차~막차 사이 `term`분, `exact_times=1`(첫차부터 배차간격 격자로 출발하는 고정 시간표).
- 서울 OSM bbox(126.70–127.25, 37.38–37.75) 밖 정류장(전체 18.8%, 504노선)은 `stop_times`·`stops` 에 넣지 않는다(도로망이 없어 OTP `IsolatedStop`). 누적 소요는 전 구간으로 계산해 안쪽 정류장의 시각은 그대로다. 안쪽 정류장이 2개 미만인 방향은 뺀다(`DroppedDirections`). `exact_times=0` 이면 OTP 2.10 이 승차마다 배차간격 전체를 대기로 더해 출발 위상과 무관하게 소요시간이 부풀었다(402번: 대기 9분 상수, 총 38.9분 → `1` 로 바꾸니 29.9분, 2026-09-12 실측). GTFS 의 `end_time` 은 배타적이고 OTP 2.10 도 `< end` 로 비교해(바이트코드 확인) 막차 시각 출발이 생성되지 않으므로, 막차 1회는 `B_{id}_LAST` 로 절대시각 stop_times 를 따로 둔다. 막차가 자정을 넘기면 24:xx 로 표기.
- `stop_times.txt`: `_T` 는 첫 정류장 00:00:00 기준 상대시각, `_LAST` 는 막차 시각 기준 절대시각. 정류장 간 소요 = `fullSectDist`(m) ÷ `sectSpd`(km/h) + 정차시간(노선유형별: 간선 38초, 지선·기타 30초, 마을·광역·공항 0). `sectSpd` 가 0 이면 18 km/h(placeholder).
- `calendar.txt`: 서비스 `ALL` 하나, 전 요일. **API 가 요일별 배차를 주지 않아 평일·주말이 같다** — 알려진 한계.
- 제외: 배차간격 없음 · 첫차·막차 파싱 실패 · 첫차==막차(API 가 시각을 모르면 둘 다 자정을 준다, 24시간 운행 아님) · 정류장 2개 미만 · 서울 bbox 안 정류장 2개 미만(2026-09-13 추가, 117인천 1개). 2026-09-12 실행에서 333개(bbox 제외 추가 후 334개). 그중 첫차==막차 82개에는 서울 노선 51개(지선 21·간선 18·광역 6·마을 3·순환 2·심야 1)가 포함되며, 이들만 지나던 서울 bbox 안 정류장 124곳이 그래프에서 빠진다. 유령 운행(새벽 3시 출근버스 안내)이 결측보다 해롭다고 보고 제외를 택했다. 나머지 251개는 대부분 경기·인천 진입 노선(245개)이고, 서울 노선 6개(자율주행 새벽A160·A504·A148·A741, 시티투어 TOUR04, 지선 8772)도 배차간격 결측으로 빠진다.

## 지하철 역 구내 통로 (이슈 #25, 2026-09-13)

- 부모역(`ST_<기준명>`, `stations.go`) 안 자식 stop(노선별 승강장)끼리 OTP 가 지상 도로망으로 환승 도보를 계산해 강남 2호선↔신분당선 182m 가 7.2분이었다(승강장 좌표가 도로에서 멀다). 파일럿 `transfers.txt` 의 `min_transfer_time`(178초)은 하한이라 도로 경로를 줄이지 못한다.
- `pathways.go`: 자식 stop 이 2개 이상인 역(229 승강장, 614 통로)에 (1) 승강장 쌍마다 양방향 walkway(통과시간 = transfers.txt 값, 없으면 직선거리÷1.0 m/s + 60초 — 단 500m 초과는 만들지 않는다: 기준명+800m 로 묶인 부모역이 실제 환승역이 아닐 수 있어서이고, 신촌 2호선↔경의중앙선 684m 가 그 경우. transfers 기반 151쌍 최대 390m·서울역 실재 폴백 5쌍 최대 434m) (2) 승강장마다 같은 좌표의 출입구(location_type 2, `EN_<stop_id>`)와 진입 120초·이탈 60초 단방향 통로. 출입구가 필요한 이유: OTP 는 통로가 있는 승강장을 도로에 직접 잇지 않는다(출입구 없이 넣자 `IsolatedStop` 273 → 480 실측) — 검증기도 같은 규칙(`pathway_unreachable_location` 229건 ERROR). 진입·이탈 초는 백엔드 `route/station_slack.go`(역 ID 앵커링 요청에 백엔드가 더하는 값)와 같아야 한다.
- 결과: 강남 환승 도보 7.2 → 3.0분, ODsay 대조 |Δ| 중앙값 3.3 → 1.0분(`docs/routing-accuracy.md`). `IsolatedStop` 273 → 292. 좌표 출발의 도로→출입구 접근은 출입구가 승강장 좌표에 있으면 도로 구간이 그대로이고 여기에 진입 2분이 더해진다(강남역 263m 옆 좌표 → 승강장 8.3분) → 아래 실제 출입구(이슈 #27). 알려진 한계: transfers.txt 쌍인데 부모역이 갈린 도봉산 1↔7호선 1쌍(파일럿 1호선 좌표가 1.1km 남쪽으로 보임)은 통로가 생기지 않아 지상 도보로 계산된다 — `gtfsgen build` 출력의 "부모역이 갈려 빠진 환승" 수로 확인.

## 코레일·민자 노선 시간표: 레일포털 Open API (이슈 #34, 2026-09-14)

- 출처 후보 비교: TAGO `GetSubwaySttnAcctoSchdulList` 는 코레일 역(옥수 경의중앙)에서 평일 89·휴일 72편이 나오지만 토요일 0건이고 열차번호가 없어 역별 목록으로 열차를 재구성해야 한다(급행·지선에서 불안정). 레일포털(철도산업정보센터 data.kric.go.kr) Open API 는 역별 시각표에 열차번호·기점·종점이 있어 (노선·요일·열차번호)로 묶기만 하면 된다. 회원가입 후 인증키를 메일로 받고 API 마다 활용신청한다(`.env` `KRIC_API_KEY`).
- `python otp/fetch_kric_timetable.py`: 노선마다 `trainUseInfo/subwayRouteInfo`(역 순서·코드) 1회 + `convenientInfo/stationInfo`(좌표, 역 코드를 줘도 노선 전체를 돌려준다) 1회 + `convenientInfo/stationTimetable`(역별, dayCd 8 평일/7 토/9 휴일) 역 수×3. 응답 시각은 "HHMMSS", 기점 도착·종점 출발은 null. 2026-09-14 실측: 코레일·공항철도·신분당·의정부·신림·김포·인천은 토요일(7)이 0건이고 휴일(9)을 토요일에도 쓴다(우이신설만 토요일 별도). 노선 코드 표는 레일포털 자료실 「운영기관, 노선, 역 코드정보 리스트(2023.02.22)」 xlsx. 대상 12노선(파일럿 코드→운영기관/선): KJ→KR/K4 경의중앙, SD→KR/K1 수인분당, GC→KR/K2 경춘, KK→KR/K5 경강, AP→AR/A1 공항철도, SB→DX/D1 신분당, UI→UL/U1 의정부, SL→SL/L1 신림, WS→UI/UI 우이신설, KP→GM/G1 김포골드, I1·I2→IC 인천1·2호선. 1·3·4호선의 코레일 구간(천안·인천·대화·오이도 등)은 서울교통공사 파일에 이미 들어 있다. 제외: 서해선(KRIC 는 소사~원시 12역뿐, 파일럿은 대곡 연장 21역), GTX-A(KRIC 에 없음).

## 경로선 shapes.txt (이슈 #75, 2026-09-19)

`shapes.txt` 가 없으면 OTP 는 정차 지점을 직선으로 이은 선을 leg 경로선으로 준다 — 지도에서 지하철이 한강과 건물 위를 가로지르고,
버스 leg 거리는 실제보다 짧다. 버스는 API 의 노선 경로로, 도시철도는 OSM 선로로 shape 를 만든다. 반영하려면 OTP 그래프를 다시
빌드해야 한다.

- **버스**(`seoulbus/path.go`, `build/shapes_bus.go`): `getRoutePath` 가 노선이 달리는 도로 위의 점을 기점→종점 순으로 준다
  (1,357노선, 점 128만 개, 빈 응답 5·좌표계가 다른 응답 2). `gtfsgen fetch` 가 `gtfs/cache/path_<id>.json` 으로 받는다.
  정류장을 경로 위에 순서대로 붙이되 앞 정류장 자리에서 구간거리×2+500m 안에서만 찾는다 — 왕복 노선은 같은 길을 반대로
  돌아오므로 창이 없으면 맞은편 차로에 붙는다. 방향(`_T0`/`_T1`)마다 그 방향 정류장이 지나는 부분만 잘라 shape
  `BSH_<노선>_<방향>` 하나를 만들고 배차 trip 과 막차 trip 이 같이 쓴다. `stop_times.shape_dist_traveled` 도 같이 쓴다.
- 경로에서 100m 넘게 어긋난 가운데 정류장이 방향당 1개 이하이고 모든 정류장(양 끝 포함)이 300m 안이면 경로를 쓰고(경로에 아직
  없는 새 정류장: 441·240번의 한강버스 선착장), 그보다 많이 어긋나면 그 방향은 shape 없이 둔다(경기·인천 면허 노선은 경로가 일부
  구간만 오는 것이 많다). 실측: 가운데 정류장이 전부 맞는 노선 1,202, 하나만 300m 안에서 어긋난 노선 28, 넷 이상이 1km 넘게
  어긋난 노선 84. 다른 조건은 다 맞는데 끝 정류장만 300m 를 넘어 shape 를 잃는 방향은 38(그 끝 정류장들의 어긋남 최대 5.6km)이다.
- API 경로에는 같은 점이 연달아 들어 있고(걸러 내면 shape 점 123만 → 115만 개) 정류장이 붙은 자리가 경로의 꼭짓점과 겹치기도 한다. 같은 좌표가
  연달아 나오면 한 번만 쓰고, 정류장별 거리는 shape 점을 이어 잰 값에서 읽어 `shapes.txt` 의 거리와 어긋나지 않게 한다(거리는 0.01m
  단위).
- **도시철도**(`otp/extract_rail.py`, `osm/rail.go`, `railpath/`, `build/shapes_rail.go`): OSM 의 철도 노선 관계
  (type=route, route=subway·train·light_rail, ref 있는 것 — 25개 ref, 선로 1,814개)에서 선로를 `otp/data/rail-ways.csv` 로 뽑는다.
  노선마다 그 노선의 선로만으로 그래프를 만들고(40m 간격으로 쪼갬) 역 좌표 250m 안의 선로 점들을 출발·도착 후보로 삼아 최단
  경로를 찾는다. 상·하행 선로는 서로 이어져 있지 않아 후보를 여럿 두고 전체 비용으로 고른다. 경로가 직선거리×2.5+800m 를 넘으면
  버린다. 노선 → OSM ref 표는 `shapes_rail.go` 의 `railRefs`.
- 정차 순서가 같은 trip 은 shape 하나(`R_<n>`)를 같이 쓴다(도시철도 trip 약 21,000편 → shape 466). 선로를 못 찾은 역 간 구간

  trip 104편은 shape 없이 둔다. 수인분당선 왕십리–청량리는 경의중앙선 선로를 같이 써서 두 ref 를 함께 본다.

## 소요시간 모델 정확도 (미보정, 알려진 한계)

- OTP 는 같은 경로를 출발시각만 다르게 여러 개 반환한다(`exact_times=0` 에서는 1분 간격, `1` 에서는 배차 격자 간격). 백엔드가 leg 서명으로 중복 제거하고, 구간 분할 빔은 중복 제거 뒤에 자른다(빔 폭만큼만 받으면 복제로 채워져 실효 폭 1).
- 수집 클라이언트는 네트워크 오류(`*url.Error`)에서 키가 든 URL 을 벗겨 원인만 남긴다. 캐시·산출물·로그에 키 포함 0건 실측(2026-09-12).
