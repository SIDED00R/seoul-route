# 도보 OSM 결함 점검 (이슈 #176)

OTP 는 OSM 을 그대로 보행망으로 쓴다. 그래서 OSM 의 낡은 폐쇄 태그, 덜 붙인 길 끝, 보행 표시가 없는 자전거길이 그대로 도보 우회가 된다(#173 양평누리체육공원 350m → 6.7km). 지도 앱은 자체 보행망을 써서 이런 결함이 없다. 이 문서는 사용자가 겪기 전에 서울 전체에서 그런 곳을 찾아 고치는 절차와 2026-10-01 첫 실행 결과다.

## 절차

세 도구를 1 → 3 → 2 순서로 돌리고, 확실한 것만 `otp/osm-overrides.json` 에 넣은 뒤 다시 3 → 2 를 돈다. 하나를 고치면 그 뒤에 숨어 있던 다음 결함이 드러나기 때문이다(아래 "2차" 참고).

```powershell
python otp/scan_closed_ways.py      # 1. 폐쇄 표시 조사 → docs/eval/osm-closed-ways-<날짜>.md
python otp/walk_detour_scan.py      # 3. 도보 우회 선별(개발 OTP 8083) → docs/eval/walk-detour-<날짜>.md, otp/data/walk-detour-flagged.json
python otp/find_walk_gaps.py        # 2. 걸린 쌍의 원인 후보 순위 → docs/eval/walk-gaps-<날짜>.md, otp/data/walk-gaps.json
# 반영: osm-overrides.json 편집 → python otp/patch_osm.py → 그래프 재빌드 → otp 컨테이너 --force-recreate → 3·2 다시
python -m unittest test_walk_audit test_patch_osm   # otp/ 에서
```

- **1. 폐쇄 표시 조사** (`scan_closed_ways.py`): 길 성격 way 의 `foot=no`·`access=no`, `highway=construction`, 이름·메모의 공사·폐쇄·통제·임시를 편집일과 함께 목록화한다. 이것만으로는 무엇이 실제로 경로를 막는지 모른다.
- **3. 도보 우회 선별** (`walk_detour_scan.py`): 지하철 출입구·따릉이 대여소에서 직선 250~1000m 안 상가·OSM 시설로 출발마다 4쌍을 뽑아 OTP 도보만 질의한다. OTP 거리 ÷ 직선 ≥ 2.0 이고 초과 ≥ 400m 이면 걸린다. `TMAP_APP_KEY` 가 있으면 걸린 쌍을 TMap 보행자 경로와도 대조한다. 같은 `--seed` 면 같은 쌍을 다시 재므로 전후 비교에 쓴다. OTP 주소는 `127.0.0.1` 로 준다(윈도우 파이썬은 `localhost` 를 IPv6 로 먼저 시도해 질의마다 2초씩 늦다).
- **2. 끊김 후보 순위** (`find_walk_gaps.py`): 걸린 쌍마다 주변 보행 그래프에 후보를 넣어 본다. 막힌 way 다시 열기(R: 1단계의 막힌 way 와 보행 표시 없는 자전거길)와 막다른 길 끝 잇기(L: 60m 안, 램프·간선도로·다리 중간 제외, 담장·철로·물·고속도로를 건너면 제외). 후보 없이도 OTP 보다 짧으면 `model`(OTP 비용·통행 제한), 후보를 다 넣으면 짧아지면 `fixable` 이고 꼭 필요한 최소 묶음을 남긴다. 1단계 목록과 겹치는 R 이 "폐쇄 표시가 실제로 경로를 막는" 곳이다.

## 반영 기준

| 등급 | 뜻 | 반영 |
|---|---|---|
| A ≤ 10m | 큰길·담장·철로·물을 안 건너는 10m 이하 잇기 | 위성사진으로 확인 후 반영(덜 붙인 끝점) |
| A 10~20m, B | 그 밖의 잇기(큰길 가로지름 포함) | TMap 경로가 그 후보를 지나거나 현장 확인 뒤 |
| R | 막힌 way·자전거길 다시 열기 | 폐쇄가 아직 유효할 수 있어 사람이 판단. 이름이 보행 통로를 뜻하는 자전거길은 규칙으로 일괄 |

## 2026-10-01 첫 실행

OTP 기본 태그 매핑은 `foot` 표시가 없는 `highway=cycleway` 를 걷지 못하게 한다. foot 없는 자전거길 12곳은 OTP 도보 거리가 모두 길 길이보다 길었고, `foot=yes` 12곳은 길이와 같았다. 서울에 그런 자전거길이 1,937개 있고, 그중 한강공원 나들목·하천 자전거길 출입로·보도육교·지하보도 같은 보행 통로가 142개였다.

| 단계 | 결과 |
|---|---|
| 1. 폐쇄 표시 | 1,820 way(공사중 776, foot=no 641, access=no 379, 이름·메모 34. 반영 후 재실행 — 반영 전 1,821 중 access=no 자전거길 출입로 1개가 규칙으로 열렸다) |
| 3. 우회 선별 | 20,743쌍 질의(26초), 848쌍 걸림, 비율 중앙값 1.33 |
| 2. 후보 | fixable 264 · model 115 · unexplained 466 · snap 3쌍, 후보 209(A 59, B 119, 자전거길 25, 막힌 way 6) |

반영(`osm-overrides.json`): 규칙 1개(이름이 `출입로|나들목|보도육교|지하보도|보행|진출입` 인 foot 없는 cycleway → `foot=yes`, 160 way)와 A ≤ 10m 잇기 17개(17개 모두 위성사진으로 확인).

**2차**: 반영 후 다시 재자 따릉이 643(동대문구민체육센터 육교 아래) 출발이 783m → 2,219m 로 길어졌다. 새로 열린 중랑천 출입로 경사로가 대여소에 가장 가까운 길이 되자 OTP 가 출발점을 그 경사로에 붙였는데, 경사로 위쪽 끝이 옆 보도와 2m 떨어져 안 이어져 있었다. 2단계를 다시 돌리자 바로 그 틈이 유일한 A ≤ 10m 후보로 나와 반영했다.

같은 20,743쌍 전후(개발 OTP):

| 항목 | 값 |
|---|---|
| 걸린 쌍 | 848 → 821 |
| 짧아진 쌍 | 70쌍, 합계 33.8km, 중앙값 389m, 최대 1,661m |
| 길어진 쌍 | 42쌍, 합계 3.0km, 최대 346m |
| 2단계가 예측한 fixable 중 반영분이 덮는 쌍 | 13쌍 중 11쌍이 실제로 25% 이상 짧아짐 |

길어진 쌍은 OTP 가 새로 열린 하천 제방길을 차도 옆 보도보다 안전한 길로 쳐서 조금 돌아가는 경우다(최대 346m). 백엔드 `/routes/plan` 으로도 월계 롯데캐슬 뒤 대여소 → 월계고등학교 2,787m → 1,126m, 양평 나들목 → 테니스장 1,159m(#173 그대로)를 확인했다.

## 남은 판단

- **TMap 키**: B 등급 잇기와 R 후보는 위성사진만으로는 판단이 어렵다. SK open API(openapi.sk.com)에서 TMap 보행자 경로 키를 받아 `.env` 의 `TMAP_APP_KEY` 에 넣으면 3단계가 걸린 쌍을 TMap 과 대조하고, 2단계 표의 TMap 열(후보를 TMap 경로가 지나는지)이 찬다. TMap 경로가 지나는 후보는 반영 근거가 된다. 이 경로는 키가 없어 실제 호출로 검증하지 못했다(응답 파싱만 단위 테스트).
- **막힌 way 6곳**: 녹사평대로 `foot=no`(2019), 장한로6·10길 `foot=no`(2024-12), 공사중 2곳(2025-11, 2026-07), 안양천 자전거길 `foot=no`(2023). 공사가 끝났는지 현장 확인이 필요하다.
- **model 113쌍**: OTP 의 보행 안전 가중치(`walk.safetyFactor`)가 큰길을 피해 돌게 만든다. 149쌍 중 30쌍은 safetyFactor 0 이면 25% 이상 짧아졌다. 모든 도보 경로에 영향을 주는 설정이라 따로 정한다.
- **폐쇄 이름인데 열린 길**: "한강 자전거길 (폐쇄)" 처럼 이름은 폐쇄인데 걷는 길로 열려 있는 way 가 1단계 목록에 있다. 합정 사례(#175)와 같은 종류로, 실제로 막혀 있으면 OTP 가 그 길로 안내한다.
