# 지하철 하차역 설비 앞 칸 (이슈 #76)

작성일 2026-09-19. 지하철 구간의 하차역에서 계단·에스컬레이터·엘리베이터가 어느 칸-문 앞에 있는지 상세 화면과 안내 화면에 보여 준다.

## 자료

공공데이터포털 「서울교통공사_빠른하차정보」(`apis.data.go.kr/B553766/inout/getFstExit`, 활용신청 필요, `.env` 의
`DATA_GO_KR_KEY`). 2026-09-19 실측: 2,358행·276개 역, 서울교통공사 1~8호선만(2호선 450 · 5호선 443 · 3호선 362 · 6호선 308 ·
7호선 302 · 4호선 278 · 8호선 127 · 1호선 88). 9호선·신분당선·코레일 구간은 없다.

| 필드 | 뜻 | 실측 |
|---|---|---|
| `lineNm`·`stnNm` | 노선·역 | "서울역" 만 끝에 "역" 이 붙는다 |
| `upbdnbSe` | 상행·하행 | 1,179행씩 |
| `drtnInfo` | 그 방향 열차가 향하는 다음 역(방면) | 종점은 자기 역 이름, 응암은 값 없음 |
| `qckgffVhclDoorNo` | 칸-문 | "3-3". 예외: "NA-NA", "3-2,3-3 사이" 류 4건 |
| `plfmCmgFac` | 설비 종류 | 계단 1,259 · 엘리베이터 563 · 에스컬레이터 536 |

**설비가 어느 출구·환승 통로로 이어지는지는 자료에 없다**(환승통로를 언급한 행 61개뿐, 출구 번호는 0). 그래서 "몇 번 출구·어느 노선
환승에 빠른 칸" 은 만들 수 없고 설비 앞 칸만 보여 준다.

## 동작

- 수집: `cd backend && go run ./cmd/fastexit` → `otp/data/fast-exit.json`(API 응답의 행 그대로, 3회 호출). 서버는 기동할 때 이 파일만
  읽는다(`FAST_EXIT_JSON`, Compose 는 `/data/fast-exit.json` 마운트). 파일이 없으면 경고만 남기고 표시 없이 돈다. **Compose 를 띄우기
  전에 파일을 만들어 둔다** — 없는 경로를 마운트하면 Docker 가 그 이름의 빈 디렉터리를 만든다.
- 조회(`internal/fastexit`): 지하철 leg 의 노선 이름("4호선")·하차역·하차 직전 정차역(중간 정차가 없으면 탑승역)으로 찾는다. 직전
  정차역 쪽으로 가는 방향(상행·하행)의 반대편 행을 고른다. 역이 자료에 없거나 직전 정차역이 어느 방면과도 맞지 않으면 비운다(틀린 칸을
  보여 주지 않는다).
- 역 이름 맞추기: 괄호 뒤("사당(4호선)")와 끝의 "역"("서울역")을 뗀다. 이름이 바뀐 역은 옛 이름으로 맞춘다 — 자료의 276개 역을 생성
  GTFS(국가교통DB 2025-03 역 이름)의 1~8호선 역과 대조해 안 맞은 것은 불암산(당고개)·자양(뚝섬유원지)·이수(총신대입구) 셋이다.
- 응답: leg `fast_exit: [{"facility": "에스컬레이터", "doors": ["3-3", "8-1"]}, …]`. 순서는 에스컬레이터·계단·엘리베이터, 칸은 앞에서부터.
- 앱: 상세 화면의 구간 줄과 안내 화면 아래 구간 줄에 "내릴 때 · 에스컬레이터 1-1 · 계단 1-1, 5-2 · 엘리베이터 2-3".

- `go vet`·`go test ./...`(DB 포함) 통과, `flutter analyze` 무경고·`flutter test` 109개 통과.
- 실제 자료로 서버 기동: `fast exits loaded stations=276`. 서울역→강남역(4호선→2호선) 응답에서 사당(4호선) 하차는 남태령 방면 행
  (에스컬레이터 1-1 · 계단 1-1, 5-2 · 엘리베이터 2-3) — 원자료의 "하행 남태령" 행과 일치. 신분당선 leg 는 비어 있다.
- 에뮬레이터: 상세 화면 `docs/app/26-fast-exit-detail.png`, 안내 화면 `docs/app/27-fast-exit-guide.png`. 오류 로그 0건.
