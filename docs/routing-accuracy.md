# 경로 정확도 평가

경로 변경은 대표 OD를 고정된 시각·요일로 실행해 이전 결과와 비교합니다. ODsay는 참고값이며 실제 운행 가능 여부는 생성 GTFS와 OTP 응답을 함께 확인합니다.

## 실행

```powershell
Set-Location backend
go run ./cmd/odcompare -at 08:30 -on 2026-09-14
go run ./cmd/odcompare -at 08:30 -on 2026-09-14 -ref ../docs/eval/2026-09-15-194638.json
```

`-ref`는 저장된 ODsay 값을 재사용하므로 API 호출을 소모하지 않습니다. 출력은 `docs/eval/<시각>.json`과 `.md`입니다.

다음 지표를 비교합니다.

- 우리 경로와 ODsay의 소요시간 차이 중앙값·사분위
- 절대 오차 중앙값
- 상위 3개 수단열 일치 수
- 경로가 없거나 실제 탑승 연결이 끊긴 OD
- 설정 변경 전후 응답시간

현재 보관하는 기준선은 `docs/eval/2026-09-15-194638.*`입니다.

## 현재 모델

- 입력은 서울 bbox로 제한합니다.
- 장소명이 역이고 1km 안에 같은 이름의 부모역이 있으면 OTP stop ID로 요청합니다.
- 역 ID 출발·도착에는 진입 120초, 이탈 60초를 더합니다.
- 후보 점수는 출발 대기 + 여정 소요 + 환승 240초 + 따릉이 대여 300초입니다.
- 최선보다 30분 넘게 느린 후보는 제외합니다.
- 지금 출발은 첫 대중교통 탑승을 실시간 도착정보로 보정합니다.
- 도보·따릉이 구간에는 신호 횡단보도 기대 대기를 더합니다.

## 변경 검증

1. 변경 전 기준 JSON을 보관합니다.
2. 동일한 OTP 그래프·날짜·시각으로 변경 전후를 실행합니다.
3. 수단열이 바뀐 OD의 `legs`, 출발 시각, 환승 연결을 직접 확인합니다.
4. GTFS나 OTP 설정을 바꿨으면 그래프를 다시 빌드하고 서버를 재기동합니다.
5. 개선된 OD만 보지 않고 전체 지표와 경로 없음 수를 비교합니다.

## 알려진 오차원

- 버스 시간표는 대표 배차와 구간 속도의 근사입니다.
- 일부 도시철도 노선은 파일럿 시간표를 사용합니다.
- 역 진입·환승시간은 역·방향별 실측 행렬이 아닙니다.
- 실시간 보정은 첫 탑승 중심이며 결행 전체를 GTFS-RT로 반영하지 않습니다.
- ODsay 값은 같은 날짜·시각의 원시 시간표 정답이 아닙니다.
