# 경로 정확도 조사·개선 기록 (2026-09-12, 이슈 #13)

사용자 관찰: 서울역→강남역이 55분으로 길다. 조사 결론은 **알고리즘이 아니라 데이터·모델링**이 원인이라는 것이다.
OTP 2.10 의 Range RAPTOR(대중교통)와 A*(도보·자전거)는 주어진 모델에 대해 exact 라 ULTRA·CSA·Trip-Based 로 바꿔도 답이 바뀌지 않는다(속도만 바뀐다).
문헌 요약과 OTP 설정 분류는 이 파일 끝에 둔다.

| # | 원인 | 실측 | 조치 | 결과 |

## 순위·다양성·응답시간 (사용자 요청 2026-09-12: 전환이 잦은 후보는 뒤로, 도보·따릉이 우대 금지)

| 변경 | 내용 | 근거 |

| 순위 함수 `rank()` | 점수 = 소요시간 + 환승 1회당 4분 + 따릉이 대여 5분. 최선보다 30분 넘게 느린 후보 제거 | 6개 OD 상위 3개 16건 중 따릉이 6건이 전부 1순위보다 20~80분 느린 후보로 끼어 있었다(홍대입구→잠실 따릉이 122분 vs 2호선 38분) |
| 수단별 3회 호출 | 전체 + 지하철만 + 버스만을 병렬로 불러 합침 | OTP 는 지배되지 않는 여정만 돌려줘 직행 노선이 있으면 후보가 1~2개(홍대입구→잠실은 first=60 에도 2호선 하나) |

## 남은 결함 (이슈)

- #12 역 구내 스냅: 좌표 대신 역 ID(`stopLocation`)로 요청하면 54.3→39.8분. GTFS 부모역 + 백엔드 앵커링으로 해결 예정. 527역 중 18% 가 같은 부류.
- GTFS 정류장 23% 가 OSM bbox 밖(`IsolatedStop 5,264`) → 광역노선 종점 잘림. shapes.txt 부재로 버스 leg 거리 19% 과소.
- 실측 대조(ground truth): ODsay Lab Basic 30콜/일(개인 가입 필요). 카카오·네이버는 대중교통 경로 API 없음.

## 문헌·설정 요약

정확도(최적해)에 영향: `areaVisibility`(이 데이터에선 무효), OSM bbox, `searchWindow`, `maxAccessEgressDuration`, `maxNumberOfTransfers`, GraphQL `first`.
선호 가중(어떤 최적해를 고를지): `walkReluctance`, `transferSlack`, `walk.speed`, `bicycle.speed`, `subwayAccessTime`.
다양성만: `itineraryFilters.*`, `numItineraries`.
OTP 2.x 는 다기준 Range RAPTOR + A* 만 구현. via 는 `visit` 의미, #6360(경유역을 통과만 하는 경우) 미해결.
검증 지표(문헌): 소요시간 비율의 중앙값·사분위, 노선집합 Jaccard, top-k 재현율, Pareto 최적 비율(OTP TrakPi). 편향 5%p 검출에 OD 120~150쌍.
