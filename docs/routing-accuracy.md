## 첫 탑승 실시간 보정 (이슈 #17, 2026-09-12 밤)

예측은 시간표(OTP)로, 실시간은 후보가 나온 뒤 재계산·순위 조정에만(사용자 결정). `backend/internal/realtime`.

- 버스: 서울 버스 도착정보 `getArrInfoByRouteAll`(노선당 1콜, 정류장별 exps1/exps2 초). "출발대기·운행종료"는 예측 없음.
- 지하철: 열린데이터광장 `realtimeStationArrival`(역당 1콜). `barvlDt>0` 또는 도착·진입(arvlCd 0/1)만 믿고, 같은 노선(subwayId)·같은 방면(다음 정차역) 열차만 쓴다. 미정(barvlDt 0, 운행 중)은 건너뛴다.
- 상위 8개 후보의 첫 대중교통 leg 만. 접근 도보 시간 안에 오는 차는 놓친 것으로 보고 다음 차를 쓴다. 노선·역별 30초 캐시, 타임아웃 5초, 실패 시 시간표 값 유지(Warn 로그).
- 보정 방식: 탑승 이후 leg 는 delta 만큼, 탑승 전 leg·출발도 같이 당기되 출발이 지금보다 앞서지 않게. 소요시간은 옮긴 Start·End 로 다시 잰다.
- **함께 고친 것**: OTP 의 `duration` 은 출발 시각부터라 출발 전 대기가 빠져 있었다 → `depart_in_sec` 을 채우고 순위·앱 표시를 `depart_in + duration`(지금부터 도착까지)으로 통일. 첫 구현에서 이걸 빼먹어 지하철 후보가 −40분 같은 비정상 보정을 냈다(시간표 다음 열차 00:04 vs 실시간 도착 중).
- 실측(23:33): 서울역→강남 후보 7개 전부 보정, 402번 −8.6분·4호선 −0.9분·421번 +0.2분. 홍대입구→잠실 2호선 +1.9분. 여의도 9호선은 실시간 미정으로 시간표 유지. API 키 인코딩(포털 키는 URL 인코딩 형태)을 안 풀어 처음엔 전부 실패했다 → gtfsgen 과 같은 `QueryUnescape`.
- 캐시 ETA 는 조회 시각 기준 상대값이라 읽을 때 경과시간을 뺀 사본을 쓴다(안 빼면 30초 안 재조회에서 이미 지나간 차를 탈 수 있다고 계산 — Codex 지적). 컷(최선+30분)은 보정 뒤에만 건다(보정 전에 자르면 최선이 늦어져도 후보를 되살릴 수 없음 — Codex 지적).
- 한계: 첫 탑승 이후 환승 연결은 시간표대로 옮기기만 한다(재탐색 없음). 지하철 실시간은 barvlDt 가 0 인 열차가 많아 커버리지가 낮다.

## ODsay 대조 평가셋 (이슈 #22, 2026-09-13)

`backend/cmd/odcompare` 가 대표 OD 20쌍(지하철 직행·환승·한강 횡단·외곽·대형역 층화)을 우리 Planner 와 ODsay Lab `searchPubTransPathT` 로 한 실행에서 나란히 풀어 `docs/eval/<시각>.md|json` 에 남긴다. 카카오·네이버는 대중교통 경로 API 가 없어 ODsay(개인 무료 30콜/일) 가 유일한 자동 참조계다. ODsay 는 정답이 아니라 편향 방향을 보는 기준이다. ODsay 는 출발 시각 파라미터가 없어 시각 무관 대표값을 돌려주므로 우리 쪽 `-at` 시각과 기준이 같지 않다. 대신 기준선이 고정되니 같은 `-at` 으로 재실행한 전후 비교는 유효하다.

첫 실행(`-at 08:30`, 시간표만, `docs/eval/2026-09-13-0541.md`):

- Δ(우리 − ODsay) 중앙값 −0.1분, 사분위 −2.0 ~ +1.0, |Δ| 중앙값 2.0분(상암→광화문 포함 기준, 빼고 계산하면 1.5분). 상암→광화문을 빼면 19쌍 전부 ±7분 안.
- ODsay 1순위 수단열이 우리 상위 3개 안: 19/20. 유일한 불일치는 노원→왕십리(우리 4호선>2호선 38분 vs ODsay 7호선>경의중앙선 37분, 1분 차).
- 편향: 지하철 직행 구간(신촌→성수·사당→강남·성북→동대문·석계→왕십리)은 우리가 2~4분 빠르다 → 역 진입·환승 도보가 낙관적(외부 검토 6번). 환승 구간(구로디지털→신논현 +4.8, 목동→압구정 +6.5, 용산→고속터미널 +3.3)은 우리가 느리다 → 환승 통로 거리·9호선 급행 부재 후보.
- 상암→광화문은 ODsay 1순위가 버스 470(41분)인데 우리는 공항철도>5호선 26분. ODsay 기본 정렬이 최단이 아닌 사례다. 도구 집계에는 들어가 있고(중앙값·사분위라 영향 작음), 해석할 때 이 쌍은 빼고 읽는다.
