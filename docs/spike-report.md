# OTP·외부 API 제약

현재 구현이 전제로 삼는 확인 사항만 정리합니다.

## OpenTripPlanner 2.10

- Java 25가 필요합니다.
- `BICYCLE_RENTAL`은 `WALK`와 함께 요청합니다.
- via는 대중교통 탐색에서 사용하고, 구간별 수단 고정은 백엔드가 구간 탐색으로 결합합니다.
- GTFS가 없으면 빌드가 성공해도 정류장 0개 그래프가 만들어질 수 있으므로 빌드 로그를 확인합니다.
- 버스 frequency trip의 앞뒤 차량 표시는 사용할 수 없어 GTFS 배차간격을 별도로 제공합니다.

## 서울 열린데이터광장

- 따릉이 `bikeList`는 한 요청 최대 1,000행입니다.
- `list_total_count`는 전체 수가 아니므로 짧은 페이지가 나올 때까지 조회합니다.
- API 키가 URL 경로에 들어가므로 요청 URL을 로그에 남기지 않습니다.

## T-data 신호 잔여시간

요청 시점 횡단보도 대기에 사용하지 않습니다.

- 같은 API는 5분에 한 번만 호출할 수 있습니다.
- 응답은 한 교차로의 과거 로그이며 좌표가 없습니다.
- `itstId`와 OSM 횡단보도를 연결할 공개 매핑이 없습니다.

횡단보도 대기는 OSM 위치와 정적 기대값을 사용합니다.

## 품질 게이트

- OTP 그래프의 정류장 수가 0이 아닐 것
- GTFS validator 오류가 없을 것
- 서울 bbox 안의 고립 정류장과 연결되지 않은 환승 수를 확인할 것
- 대표 OD에서 정상 경로와 실패 요청 본문을 확인할 것
